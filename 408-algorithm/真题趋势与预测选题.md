## 如何解读（不是押题概率）

- **2009—2019**：链表、数组和树轮流出现，双指针、原地操作、递归、划分是可迁移的基本功。
- **2020—2025**：题目载体扩展到多个有序数组、图、顺序存储二叉树与矩阵；因此不应只刷链表与数组。上述时间分段仅为复习组织方式，不代表统计学上的必然趋势。
- **禁止用“多年未考所以今年必考”作推断**。预测指复习优先级而非命中率。

## 每日新题选题规则（供后备题库维护）

1. 约 **45% 经典与真题高频思想**：双指针（含快慢指针）、哈希/辅助标记、原地逆置、归并、二分、划分、递归。
2. 约 **35% 近年跨结构综合变式**：图的 DFS/BFS 与环/连通判定、树的遍历与祖先、多个有序序列协同扫描、顺序存储与下标映射。
3. 约 **20% 补盲与预测训练**：矩阵/稀疏表示、栈队列的算法化应用、空间限制下的设计、边界条件复杂的题。
4. **每题须写明**：真题关联（有证据才标年份）、选题理由、方法标签、朴素解、简单优化解、标准 C 代码与 main、动画推演、时空复杂度、考场性价比、巩固题及完整答案。预测题必须显著标注“预测练习/原创变式”，不得冒充真题。
5. **不重复**：先查 lessons.json 与 pending-lessons.json 的 id、主题和核心思想；可以复习同一方法的不同应用，但不得连续安排换皮题。保持现有 JSON schema 与 Actions 发布逻辑不变。
6. **按考试性价比**：优先能在 15—20 分钟内手写的算法；不以竞赛难题代替 408 训练。

## 考前 67 天执行计划（2026-10-13 至 2026-12-18）

| 阶段 | 日期 | 目标 | 每日算法训练 |
|---|---|---|---|

### 编排硬规则
- 每天仅一题，不挤占数学和 408 四科滚动复习；隔五天的复现替代当日新题，不额外叠加。
- 先手写思路与 C 代码，再看朴素法和优化法；错题标记为 3 天、7 天、14 天后复现。
- 每 7 天复盘一次：是否能独立写出、是否漏边界、复杂度是否正确；根据薄弱项调整后备队列。
- 新增课程应在原有 JSON schema 之外避免随意增字段；训练阶段和预测理由可写入课程的 tips、constraint 或维护文档。
- 现有队列截至 10/18；10/19 起须由人工或受控生成流程提前准备并测试题目。**现有 Actions 不具备凭空生成并审核新题的能力**，不能把后备队列当成已经覆盖到考前。
- 不因为队列不足而重复发布旧题或伪称发布成功；每日发布脚本和网站部署保持独立。
