      408 OPERATING SYSTEM · MEMORY MAPPED FILES
      
 
      内存映射文件｜从虚拟地址到磁盘块
      
 
      第 61 题概念精讲：弄清“文件内容 ↔ 进程虚拟地址空间”的真正含义，把 mmap、文件系统、页表三层职责一次串通。含完整数字例子、6 步交互推演与可折叠自测。
      
 
      先记主结论：mmap 将进程的一段虚拟地址区域关联到某个文件及文件偏移；文件系统管理文件逻辑块到磁盘物理块的对应；页表管理虚拟页到物理页框的映射。它们可以协同工作，但不是同一张映射表。
      
 
      页大小：4 KB文件大小：12 KB磁盘块大小：4 KB（仅本例）逻辑块号从 0 开始
      

 
      
  
      01 / mmap 究竟建立了什么关联？
      
  
      假设磁盘上有文件 A.txt，前 11 字节是 HELLO WORLD，全文件大小 12 KB。进程将文件从偏移 0 开始的 12 KB 映射到虚拟地址 0x10000～0x12FFF。程序读虚拟地址 0x10000，逻辑上就是访问文件偏移 0 的字节 H；读 0x10001 对应字节 E。进程无需先用 read() 把整段文件复制到自己的缓冲区。
      
  
      
   
      程序看到的虚拟地址区间0x10000 ～ 0x12FFF进程自己的虚拟地址空间，未必已分配物理页框
      
   
      ↕mmap 登记：映射到 A.txt，文件起始偏移 0
      
   
      文件 A.txt 的逻辑内容第 0 ～ 12287 字节映射的“地址关联”≠ 文件全部立即装入内存
      
  
      
  
      本例计算公式：文件偏移 = 被访问的虚拟地址 − 映射区起始虚拟地址 + 映射文件的起始偏移。本例的文件起始偏移为 0，因此 0x11064 − 0x10000 = 0x1064 = 4196 字节。
      
  
      
   
      进程虚拟地址映射文件文件偏移
      
    
      0x10000～0x10FFFA.txt0～4095 字节
      
    
      0x11000～0x11FFFA.txt4096～8191 字节
      
    
      0x12000～0x12FFFA.txt8192～12287 字节
      
   
      
  
      
  
      第一层只回答：“这个虚拟地址代表 A.txt 的第几个字节？”它不负责确定这个字节落在哪一个磁盘物理块中。
      
 
      

 
      
  
      02 / 文件偏移怎样找到磁盘块？
      
  
      这是文件系统的职责。文件内部按逻辑块顺序编号，但文件的实际磁盘块可能不连续。假设 A.txt 有以下块映射（纯教学示例）：
      
  
      
   
      文件逻辑块文件偏移范围磁盘物理块
      
    
      逻辑块 00～409550
      
    
      逻辑块 14096～8191108
      
    
      逻辑块 28192～1228773
      
   
      
  
      
  
      以上面得到的文件偏移 4196 为例：4196 = 1 × 4096 + 100，因此是文件第 1 号逻辑块中的第 100 字节。文件系统查询文件的块索引（例如索引节点信息），发现逻辑块 1 对应磁盘块 108，块内偏移 100。
      
  
      
   
      文件偏移 4196 字节4096 + 100
      
   
      ↓除以每块 4096 字节
      
   
      逻辑块 1，块内偏移 100逻辑块是文件中的位置编号
      
   
      ↓查询文件系统中的块映射信息
      
   
      磁盘块 108，块内偏移 100物理块号只是该例的假设，不要求连续
      
  
      
  
      第二层只回答：“如果需要从磁盘找数据，这个文件偏移对应哪个磁盘块？”实际文件可能有空洞、缓存或更复杂的组织方式，不是每个文件字节都必须有已分配的磁盘块。

      ① 进程访问一个虚拟地址

      关键时序：CPU 首先按页表进行地址转换。只有当所需页面不在内存而发生缺页、并且必须从后备文件取得数据时，才需要沿着 mmap → 文件系统 的方向定位文件数据。若已驻留内存，就直接访问物理页框；若数据已在页缓存中，也未必发生磁盘 I/O。
      
 
      

 
      
  
      04 / 三张“映射表”，分别归谁管？
      
  
      
   
      mmap / 虚拟内存区域信息
      虚拟地址区间 ↔ 文件及其偏移。说明虚拟地址背后对应什么文件内容。
      
   
      文件系统 / 文件块索引
      文件逻辑块 → 磁盘物理块。说明文件数据在外存中如何组织。
      
   
      页表 / 地址转换
      虚拟页 → 物理页框。说明当前已驻留页面在内存的哪里。
      
  
      
  
      三个关系可以串起来协同完成一次缺页处理，但“能间接找到”不等于“某个机制直接提供这张映射表”。页表通常不直接保存“文件虚拟页号 → 磁盘物理块号”的简单对应表。
      
  
      一口气记住：mmap 管这个地址对应哪个文件字节；文件系统管这个文件字节在磁盘何处；页表管这个虚拟页当前在内存何处。
      
 
      

 
      
  
      05 / 第 61 题：为什么“页到磁盘块的映射”不选？
      
  
      这种间接对应可以存在，但是 mmap 机制本身并不直接建立“虚拟页 → 磁盘物理块”的映射表。它只登记虚拟地址区域关联的文件与偏移；真正的文件块定位交由文件系统。如果因此把第二层也算成 mmap 的“直接功能”，就是把不同机制的责任混在一起。
      
  
      另一个反例：匿名零填充页首次访问时可以只分配内存页框，并没有对应的文件磁盘块。即使是文件映射，文件空洞、页缓存等情况也说明“每个虚拟页固定对应一个磁盘块”并不成立。
      
  
      同一文件还可以被进程 A 映射到虚拟地址 0x10000，被进程 B 映射到 0x80000；它们的虚拟地址不同，却能在适当的共享映射条件下使用相同的物理页框。物理页框不属于某个进程固定独占的一份文件拷贝。
      
  
      写入也别混淆：共享、可写映射的改动可以反映到对应文件（回写可能延迟）；私有写时复制映射在发生写入后通常不把私有修改写回原文件。考研选择题主要把握“映射文件简化文件访问、支持共享，以及 I/O 由系统按需处理”。
      
 
      

 
      
  
      06 / 先独立判断 · 三道概念自测
      
  
      
   
      题 1：mmap 后，文件的所有页面是否立即进入物理内存？
      否。建立的是虚拟地址到文件内容的关联；访问时可按需装入。映射区有虚拟地址，不代表相应物理页都已经驻留。
      
   
      题 2：访问 0x11064 必然读磁盘块 108 吗？
      否。若页表已建立有效映射，就可直接访问内存；即使发生缺页，也可能命中页缓存而无需磁盘 I/O。磁盘块 108 是教学例子中所需文件数据的磁盘位置。
      
   
      题 3：两个进程映射同一文件，虚拟地址不同，能共享数据吗？
      能。在共享映射及适当同步条件下，可映射到相同的物理页框；各进程虚拟地址不要求一致。
